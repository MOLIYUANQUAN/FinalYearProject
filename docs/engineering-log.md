# Friday 工程记录

[计划](plan.md)只写方向和标准。这里记录每一项怎么做的、测过什么、为什么这样决定。

## 现在怎么工作

1. **打开。** 按 Ctrl+Alt+F。服务端读日历和待办（最多旧 1 分钟），原样排成「今天」卡片，再算出此刻最该说的那一句，一起交给页面。全程不经过模型，所以快、不花钱、不会说错。没接待办时卡片里完全不出现待办。
2. **问。** 每一轮都带着此刻时间、今天到下周日的日历、没做完的待办、档案和记得的事。日历分「这周 / 下周」，每天写明日期、星期和几项，已结束和进行中的单独标出。日子、星期、数目、截止日都由服务端算好，模型不用自己推算。
3. **说一次。** 顺口提到的长期事实它会记下；纠正一次就改对。记忆只存在本机（`data/memory/facts.json` 不进 Git）。要去做的事进待办，不是记忆。
4. **做事。** 发邮件、改日程、删东西之前先确认一次；只有它真在等确认时，「好的」才算同意。待办记下和划掉直接做，页面给「撤销」，撤销走 `/api/undo`，不经过模型。

刷新页面不丢对话。同一天两小时内回来算同一次会话，否则重新开场。

## 一按就在：交付细节

- 「F.」图标、独立窗口。窗口用自己的浏览器资料（不带主浏览器的扩展），第一帧就是对的大小，而且一定在最前面。
- 常驻进程监听 Ctrl+Alt+F：一按就出来，再按就收起。开机就在后台准备好；代码变了才换新进程。
- 「今天」卡片直接用日历原样数据，跟随系统深色；放了几个小时再叫出来，开场自动刷新。
- 那句话按情况挑一件说：快开始的；正在上的，和紧接着的下一件；今明两天要紧的（导师、开会、截止、考试）；接下来空多久；周末或这周后面都空着。钟点说成「中午 12 点」「下午 3 点半」，课的类型说中文（讲座、实验课、线上答疑）；要赶过去的才说地点。
- 日历时间一律先换成本地钟点（导入的课表给的是 UTC）。
- 日程每轮自带：今天到下周日读一次，开场和对话共用。对话最多用 5 分钟前读的；窗口叫回时后台先读好；Friday 写过日历就重读。
- Google 授权过期时，后台服务只提示怎么重新登录，绝不突然弹出授权页。

## 待办：交付细节

- `TASKS_BACKEND=none`（默认）| `mock` | `google`。没接入时工具不注册，卡片和对话都不提待办。
- Google Tasks 用单独 token（`secrets/google_tasks_token.json`），登录：`scripts\auth_google_tasks.py`。默认清单 `@default`；截止只记日期。
- 「周四」「下周一」「10月22日」由 `todos.parse_due` 算成日期；`add_task` / `complete_task` 返回写好的 `say`，模型原样照说。
- 同名已在清单里：回「已经记着了」；改截止日：回「改好了」并可撤销。
- 开场卡片多一栏「待办」（过期 / 今天 / 明天）；那句话把今天截止的放最前，晚上 5 点后提明天截止的。
- 演示种子：`data/tasks.json`（mock 只改内存，不改文件）。

| 说错（编造） | 见下 | 0 |
| 未经确认的写操作 | 0 | 0 |

测试中出现过 7 类说错，都已修复并复测：

1. 「明天有课和实验」（编造）
2. 开场把明天的会说成今天
3. 课表时间早一小时（日历给的是 UTC）
4. 把「周一」算成周二
5. 把下周的课说成这周
6. 没搜邮件就说邮件里没有
7. 数错几节课

多数的修法是同一个：时间、日子、数目由服务端算好写进数据，模型只照着说。
