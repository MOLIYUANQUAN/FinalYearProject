# Friday — 路线

> 一个认识你、替你盯着生活碎片、带主见回应你的个人代理。  
> 判断标准只有一个：一个普通的周二，你会不会主动打开它。

设计戒律和门禁见 [product-north-star.md](product-north-star.md)。这份文档只回答：接下来做什么、按什么顺序、怎样算做成。

## 它在你一天里的五个时刻

所有界面和功能只为这五件事服务：

1. **打开** — 第一句话就是你此刻最该知道的事。
2. **问** — 日程、邮件、笔记、你告诉过它的事，一问就答，答的都是真的。
3. **交代** — 你随口说的事实、要做的事、想法，它都接住。
4. **回来** — 交代过的事在该出现的时候自己出现，不用你再问。
5. **做事** — 建日程、回邮件这类事替你做，动手前确认一次。

## 阶段

| 阶段 | 主题 | 状态 |
| --- | --- | --- |
| 0 | 收尾：know-me、流式、开场白、记忆闭环测完提交 | 完成 |
| 1 | 像一个 App，而不是一个网页 | 进行中 |
| 2 | 碎片会回来 | 未开始 |
| 3 | 替你做事更顺 | 未开始 |
| 4 | 评测与报告 | 冻结，等周二测试通过 |

### 阶段 1：像一个 App，而不是一个网页

- 名字叫 **Friday**，有自己的图标；独立窗口打开，没有地址栏和标签页。
- 开机后在后台准备好；桌面快捷方式 + 全局快捷键，一按就出来；代码没变就不重启，秒开。
- 视觉打磨：中文排版、行距和留白、跟随系统的深色模式、数字对齐、出字顺滑。
- 开场白排成一眼能看完的「今天」：接下来的安排按时间列好，模型只说判断。
- 写操作是确认卡片：要做什么、时间 / 收件人 / 主题，一个确认、一个取消。
- 日程和邮件的回答能点开到 Google 日历 / Gmail 原文。

验收：从想用到看到第一句话 ≤ 3 秒；连续一周工作日里至少 4 天主动打开。

### 阶段 2：碎片会回来

- 待办和截止日期放进 **Google Tasks**（手机上也能看到、能提醒）：一句话记下，做完一句话划掉。
- 开场白在日程之外加上快到期的事和真正要紧的邮件（导师、学校、截止相关）；没有就不提。
- 周日晚上 / 周一早上的开场白看一整周：哪天最满、要交什么。
- 先接现成的来源：课程截止日期的日历订阅、学校邮件转发到 Gmail（如果学校允许），不用另写代码。
- 一个轻量的「它记得的事」面板：记忆和待办能看、能删。

验收：交代过的事到点自己出现；开场白零编造；至少一次因为它而没漏掉事。

### 阶段 3：替你做事更顺

- 邮件：起草回复，确认后发出；一句话归档一批通知类邮件。
- 日程：新建、改时间、取消，都只确认一次。
- 记笔记：「记一下今天和导师聊的……」存成笔记，之后能搜到。
- 准备重要时刻：日历里有和导师的会，开场白提一句；说「准备一下」就给时间地点、现状、三个讨论点。
- 确认卡片上能直接改一个字段再确认，不用重说一遍。

验收：每个写操作只确认一次；测试里误执行为零。

### 阶段 4：评测与报告

- 周二测试通过后解冻评测；评测集取自真实使用里出现过的问题（脱敏）。
- 指标：答对率、编造率（必须为零）、误执行（必须为零）、首字延迟、每周使用天数。
- 对比 Baseline 与当前版本，产出报告需要的证据；合并 `main`、打 tag 前先问 Jimmy。

## 阶段之间的门

每个阶段做完先真用一周，看 `scripts/usage_report.py`：几天打开、首字多快、出错几次。  
没被用起来，就先修「为什么不想打开」，再往下做。

## 明确不做

手机 App、语音、多智能体、浏览器自动操作、云端部署、复杂权限、花哨的界面。  
手机端靠 Google Tasks 和 Google 日历自然覆盖。

## 协作

每做完一个步骤或功能就提交并推到 `develop`，提交不带任何 co-author。
