# Friday — 计划与进度

> 一个认识你、替你盯着生活碎片、带主见回应你的个人代理。只为 Jimmy 一个人工作。  
> 更新于 2026-10-16 · 分支 `develop`

这是唯一的计划文档：方向、标准、进度都在这里。设计戒律的来历见 [product-north-star.md](product-north-star.md)。

**一句话判断：一个普通的周二，你会不会主动打开它？会，才算做成。**

---

## 标准：我们按什么做取舍

1. **专注** — 只做你一天里的五个时刻（下一节），其余一律说不。
2. **简单** — 对话就是界面。没有设置页、没有菜单、看不见工具；只在真要你拍板时出现一个按钮。
3. **快就是功能** — 每一步都有秒数上限（见「质量线」）。超了就是缺陷，不是「以后再优化」。
4. **真** — 日程、邮件、记忆只来自真实数据；不知道就说不知道。编造一次就是事故。
5. **有主见** — 第一句就是答案或判断，一到四行；不摆选项菜单，不用客套收尾。
6. **细节** — 图标、窗口大小、字体、行距、深色模式、输入法回车、刷新不丢。没人会说出来，但每个人都感觉得到。
7. **端到端** — 从按下快捷键到读到有用的一句话，整条路都归我们负责：启动、服务、日历、模型、界面。
8. **信任** — 写操作只确认一次；它记得的事你看得见、删得掉；数据只在这台电脑上。

## 它在你一天里的五个时刻

| 时刻 | 应该是什么样 | 现在 |
| --- | --- | --- |
| 打开 | 第一句话就是你此刻最该知道的事 | 有：今天还剩什么、下一件是什么；今明都空时说之后最近的一件 |
| 问 | 日程、邮件、笔记、你说过的事，一问就答，答的都是真的 | 有 |
| 交代 | 随口说的事实、要做的事、想法，它都接住 | 只接住「事实」；待办在阶段 2 |
| 回来 | 交代过的事在该出现的时候自己出现 | 还没有，阶段 2 |
| 做事 | 建日程、回邮件，动手前确认一次 | 有确认闭环；卡片在阶段 1，改字段在阶段 3 |

## 质量线

| 体验 | 现在（实测） | 目标 |
| --- | --- | --- |
| 按快捷键到窗口出现 | 3.6 秒（经 Explorer 快捷方式）；直接启动 0.3–0.4 秒 | ≤ 0.5 秒 |
| 打开到第一个字 | 1.5–2.0 秒（服务热着）；刚重启约 4 秒 | ≤ 1.5 秒 |
| 不用查东西的回答，第一个字 | 0.7–1.1 秒 | ≤ 1 秒 |
| 要查日历的回答，第一个字 | 2.8–4.0 秒 | ≤ 2 秒 |
| 编造 | 测试中出现过 1 次（「明天有课和实验」），已修复并复测 | 0 |
| 未经确认的写操作 | 0 | 0 |
| 每周主动打开 | 从现在开始记录 | 工作日 ≥ 4 天 |

差距怎么补：

- **快捷键**：由开机常驻的小进程自己监听 Ctrl+Alt+F，不再每按一次就经 Explorer 起一个新进程。（进行中）
- **打开**：常驻让服务和日历一直是热的；窗口一出现就先画出接下来的安排，模型那句判断随后流进来。（阶段 1「今天」）
- **查日历**：今明两天的日程像档案和记忆一样每轮自带（短时缓存，写日历后立刻刷新），问「今天 / 明天」不用再现查。（阶段 1）

### 阶段 1 剩下的

1. **视觉打磨** — 中文排版、行距与留白、跟随系统的深色模式、数字对齐、出字顺滑。
2. **「今天」** — 开场先画出接下来的安排（时间对齐，一眼看完），模型只补一句判断；窗口放了几个小时再叫出来时，开场自动刷新。
3. **确认卡片** — 要做什么、时间 / 收件人 / 主题，一个确认、一个取消。
4. **能点开原文** — 日程和邮件直接链到 Google 日历 / Gmail。
5. **查日历提速** — 今明日程每轮自带。

## 之后

### 阶段 2：碎片会回来（产品的灵魂）

- 待办和截止日期放进 **Google Tasks**：一句话记下，做完一句话划掉；手机上的 Google 日历 / Tasks 也看得到、会提醒。
- 开场白在日程之外加上快到期的事和真正要紧的邮件（导师、学校、截止相关）；没有就不提。
- 周日晚上 / 周一早上的开场白看一整周：哪天最满、要交什么。
- 先接现成的来源：课程截止日期的日历订阅；学校邮件转发到 Gmail（如果学校允许），不另写代码。
- 「它记得的事」：记忆和待办能看、能删。

验收：交代过的事到点自己出现；开场白零编造；至少有一次，你因为它的提醒没漏掉一件事。

### 阶段 3：替你做事更顺

- 邮件：起草回复，确认后发出；一句话归档一批通知类邮件。
- 日程：新建、改时间、取消，每次都只确认一次。
- 笔记：「记一下……」存成笔记，以后能搜到。
- 重要时刻：日历里有和导师的会，开场白提一句；说「准备一下」，就给出时间地点、现状和三个讨论点。
- 确认卡片上能直接改一个字段再确认，不用整件事重说一遍。

验收：每个写操作只确认一次；测试里误执行为零。

### 阶段 4：评测与报告

- 周二测试通过后解冻；评测集取自真实使用里出现过的问题（脱敏）。
- 指标就是上面的质量线，再加答对率；对比 Baseline 和当前版本，产出报告需要的证据。

## 为什么这个方向是对的

- **价值在整合。** 日历、邮件、记忆、待办各有各的 App，但没有一个会用同一个声音、在同一个时刻，把它们合成一句「你现在最该知道的事」。这就是 Friday 存在的理由。
- **开场白就是首页。** 每天用不用，取决于打开那三秒有没有用。所以阶段 1 先把「打开」做到极致。
- **「回来」是灵魂。** 记得住只是数据库，到点自己出现才是代理。阶段 2 决定它是工具还是伙伴。
- **站在现成的基础设施上。** Google 日历 / Gmail / Tasks + OAuth：不自建同步，不做手机 App，手机端自然就有了。
- **FYP 依然成立。** 阶段 0–3 是 Application 层，阶段 4 是 Evaluation；质量线就是评测指标，真实使用就是证据。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 周二测试没过：打开有摩擦、不够快、说的话没用 | 每个阶段做完先真用一周，看使用报告；没被用起来就先修原因，不往下做 |
| 「要紧邮件」判断不准，开场白变吵 | 只在有把握时提；宁可漏提，也不制造噪音 |
| 模型表现波动：客服腔、编造 | 每次改动都跑同一组实测：导师、明天、记忆闭环、随口回应、写操作确认 |
| 学校 Outlook 接不进来 | 转发到 Gmail（如果允许）；否则明确说没接入 |
| 杀毒软件拦截启动脚本 | 启动器用 Python，不落 .ps1；快捷方式随时 `--remove` 撤掉 |

## 明确不做

手机 App、语音、多智能体、浏览器自动操作、云端部署、复杂权限、花哨的界面。
