# Friday

> **交给 Friday，然后就可以忘了。**

![Friday 的「今天」：今天和明天的安排，和此刻最该知道的那句话](img/friday-today.png)

## 一个周二

（示例，数据是编的）

周二 8:40，你按下 Ctrl+Alt+F。Friday 已经在说话：

> 早上好，Jimmy。10:00 COMP34111，还有 80 分钟。  
> Lab 3 周四截止，你还没开始；今晚 7 到 9 点空着。  
> 王老师昨晚回信，问周五能不能提前到 2 点。

你说「帮我回可以」。它起好草稿，你点确认。前后不到一分钟。

下午 2:45，屏幕角落轻轻一下：「15 分钟后见王老师，要点在这。」这是它今天唯一一次主动找你。

这段话里的每一句，都是一个要做到的功能；不在这段话里的，都先不做。

## 四个「绝不」

只有一个 Friday，和你一段关系。对话就是界面，工具藏在后面。

1. **绝不说假话。** 日程、邮件、记忆只来自真实数据；不知道就说不知道。
2. **绝不让你等。** 按下就在，开口就是答案，不给你列选项。
3. **绝不问你已经说过的事。** 说一次，它就记住；说错了，纠正一次就改对。
4. **绝不没经过你就动手。** 读可以直接读；写、发、删，先问你一次。

做到这四条，靠一个原则：**能算的先算好，模型只照着说。** 时间、日子、几项、隔多久，都由服务端算好写进数据；开场那句话干脆整句由服务端写好。

好看、利落、细节到位，是每一次提交的标准，不是一个阶段。

## 两个数字

- **每个工作日，你都主动打开它。**
- **它说错的次数：0。**

其余的数字都是工程目标，见下面的质量线。

## 路线

按它为你做到的事命名。每一步做完，先真用一周；没被用起来，就先修原因，不往下走。

### 1. 一按就在 · 做完了，真用一周

按下 Ctrl+Alt+F，Friday 已经在那儿，而且已经在说今天：安排排好，那句话一起到。今天到下周日的日程它本来就知道，问了不用再查。10 月 16 日全量实测通过，没有一次未经确认的写操作。

### 2. 交给它就可以忘 · 下一步，和真用这一周同时做

**做到：** 你交代的事，会在对的时候回来找你。这是 Friday 的灵魂。

- 待办和截止日期：一句话交给它，放进 Google Tasks；手机上也看得到、会提醒；做完一句话划掉
- 开场白把日程、待办、记忆和要紧的邮件（导师、学校、截止）合成一句话；没有要紧的就不提
- 周日晚上 / 周一早上：看一整周，哪天最满、要交什么
- 到点它会来找你：每天最多一两次，只在真要紧时，比如会前 15 分钟把要点递给你
- 先接现成的来源：课程截止日期的日历订阅；学校邮件转发到 Gmail（如果学校允许）
- 它记得的事：你看得见、删得掉

新东西先过同一组实测，再进你每天用的 Friday。

**演示时刻：** 周一随口一句「Lab 3 周四交」，周四早上开场白的第一句就是它。

### 3. 替你做完

**做到：** 说一句，事情就办完，你只点一次确认。

- 回邮件：起草，你确认后发出；一句话归档一批通知
- 改日程：新建、改时间、取消
- 记笔记：「记一下……」，以后能搜到
- 准备会面：时间地点、现状、三个讨论点
- 确认卡片：要做什么一眼看清，能直接改一个字段再确认；日程和邮件能点开原文

**演示时刻：** 「帮我回王老师说可以」：草稿、确认、发出，不到十秒。

### 4. 证明它

**做到：** 用数据证明 Friday 在真实的周二里有用（FYP 的 Evaluation）。

- 周二测试通过后解冻评测；评测集取自真实使用中出现过的问题（脱敏）
- 对比 Baseline 与当前版本；下面的质量线就是指标
- 合并 `main`、打 tag 之前先问 Jimmy

## 质量线

| 体验 | 现在 | 目标 |
| --- | --- | --- |
| 按下到窗口出现 | 0.41–0.47 秒 | ≤ 0.5 秒 |
| 打开到第一个字 | 0.74 秒，卡片和那句话一起到 | ≤ 1.5 秒 |
| 问日程，第一个字 | 0.5–1.4 秒 | ≤ 2 秒 |
| 不用查东西的回答，第一个字 | 0.6–1.4 秒 | ≤ 1 秒 |
| 说错 | 测试中出现过 7 类，都已修复并复测 | 0 |
| 未经确认的写操作 | 0 | 0 |

## 不做

手机 App、语音、多智能体、浏览器自动操作、云端部署、复杂权限、花哨的界面。  
手机端靠 Google Tasks 和 Google 日历自然覆盖。
